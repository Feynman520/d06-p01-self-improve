# self-improve 플러그인 설계 문서

- 작성일: 2026-07-07
- 상태: 사용자 승인 대기 (조각 1~5 + 텔레메트리 조각 대화 승인 완료, 문서 최종 검토 단계)
- 대상 사용자: ① 개발자 본인(IRIS 워크스페이스), ② 개발자의 강의를 수강하는 교사들(깃허브 설치)

## 1. 목적과 핵심 가치

클로드코드 작업 중 **사용자가 결과를 수정·재요청하는 순간**은 "사용자가 진짜 원하는 것"과 "클로드의 첫 결과"의 차이가 드러나는 가장 값진 데이터다. 현재 이 데이터는 대화 종료와 함께 사라진다. self-improve는 이 순간들을 붙잡아 **기록 → 패턴 분석 → 재발 방지책(CLAUDE.md 규칙 / 스킬 / 스크립트·라이브러리 / MCP) 제안·적용**하는 자기개선 루프를 만든다.

## 2. 전체 구성 (배포 형태 = 클로드코드 플러그인)

플러그인 1개에 두 부품:

| 부품 | 역할 |
|---|---|
| **MCP 서버** (Node.js) | 도구 4개(`log`/`search`/`stats`/`resolve`) + 항상 표시되는 감지 지침(instructions) + 텔레메트리 전송 |
| **스킬 2개** | `/self-improve-log`(수동 즉시 기록), `/self-improve-report`(정기 보고) |

훅(hook)은 **사용하지 않는다** (사용자 결정: 세션 끝 별도 점검 없이 그때그때 감지·기록). 항상-켜짐 감지는 MCP 서버의 instructions 필드로 구현한다 — 플러그인이 설치된 모든 세션의 시스템 컨텍스트에 감지 규칙이 상주한다.

기록 방식은 **하이브리드**: 클로드의 자동 감지 + 사용자의 수동 명령(`/self-improve-log`) 병행.

## 3. 기록 (데이터 모델)

**기록 1건 = 마크다운 파일 1개** (frontmatter + 본문 4절):

```markdown
---
id: 2026-07-07-001          # 날짜-일련번호
date: 2026-07-07
project: <발생 폴더 경로>     # cwd 기준
category: 오해               # 아래 5종 중 1
status: open                 # open | resolved
related: 2026-07-01-003      # 유사 기록 연결(선택)
resolution: <적용한 해결책>   # resolve 시 기입
---
## 무슨 일이 있었나
## 사용자가 진짜 원한 것
## 교훈                       # 필수, 한 문장으로 일반화된 지식
## 해결책 후보
```

**분류 5종 (고정):** ① 오해(요구 오해) ② 지식 부족(사용자/환경 고유 사실) ③ 도구 실패 ④ 환경 문제(설정·경로·권한) ⑤ 반복 비효율(자동화 후보)

**저장 위치:** 환경변수 `SELF_IMPROVE_DIR`.
- 미설정(기본값): 현재 프로젝트의 `.self-improve/`
- IRIS: `C:\Users\User\Desktop\IRIS\_자기개선(Self-Improvement)` (하위 `records\`, `reports\`)

**MCP 도구 4개:**
- `log` — 기록 저장. 저장 전 유사 기록 자동 검색 → 있으면 `related`로 연결(반복 횟수가 패턴의 증거).
- `search` — 키워드/분류/폴더/상태 필터 검색.
- `stats` — 분류별·폴더별·기간별 집계.
- `resolve` — 해결 표시 + 적용 해결책 기입(복수 id 일괄 처리).

기록은 전부 로컬 파일. 원문 외부 전송 없음(텔레메트리는 §6의 세탁본만).

## 4. 감지 (MCP instructions에 상주하는 규칙)

**기록해야 할 4가지 순간:**
1. 결과 수정 요청 ("아니, 그게 아니라 / 다시 해줘") → 오해·지식 부족
2. 미래 규칙 선언 ("앞으로는 항상 ~") → 지식 부족
3. 도구·명령 실패 후 우회 → 도구 실패·환경 문제
4. 같은 수작업 반복 → 반복 비효율

**노이즈 필터 (기록 금지):** 새 요구 추가, 일회성 취향 조정. 판별 기준 = **한 문장 테스트**: "다음에도 써먹을 교훈을 한 문장으로 쓸 수 있는가?" 못 쓰면 기록하지 않는다. (그래서 `교훈` 칸이 필수.)

**기록 예절:** 사용자 요청 처리가 먼저, 기록은 직후. 기록 후 한 줄 알림(`📝 개선점 기록: "..." (분류)`). 사용자가 "기록하지 마" 하면 즉시 삭제. v1은 실패·수정만 기록(칭찬 기록은 v2 후보).

**알려진 한계:** 훅이 없어 감지는 클로드의 지침 준수에 의존한다. 완화책: ① instructions를 짧은 명령형으로 유지, ② 보고서에 "기록 0건 공백 기간" 표시로 누락 의심 가능화. 누락이 체감되면 훅 재도입(플러그인이라 추가 용이).

## 5. 해결 (2단계 + 재발 감시)

**① 즉시 제안:** 해결책이 "CLAUDE.md 몇 줄 추가" 수준이면 기록 직후 바로 제안 → 승인 시 적용 + `resolve`.

**② 정기 보고 (`/self-improve-report`):**
1. open 기록 전체 로드 → **패턴 묶기** (예: "한글 변환 실패 3회, 전부 표 포함 문서")
2. **처방 사다리** — 반드시 가벼운 칸부터 검토: CLAUDE.md 규칙 → 스킬 제작 → 스크립트/외부 라이브러리 → MCP 도입·제작. ("1줄로 될 일에 MCP 만들기"를 구조적으로 차단)
3. **보고서 출력** — 처방별 근거(기록 n건)/내용/예상 효과/적용 비용, **효과 대비 비용 순 정렬**. 파일로도 저장: `reports/YYYY-MM-DD-보고.md`
4. **승인 → 적용 → 일괄 resolve**

CLAUDE.md 처방 시 "어느 레벨에 넣을지"를 근거와 함께 제시(범용 표현: "적절한 스코프 위치를 제안하라". IRIS의 레벨 고유성 규칙은 IRIS 루트 CLAUDE.md가 커버하므로 플러그인에 IRIS 고유 규칙을 넣지 않는다).

**③ 재발 감시:** resolved인데 같은 문제가 재기록되면 보고서 최상단에 ⚠️ "처방 무효" 경고.

**권장 주기 (강제 아님):** 기록 10건 이상 또는 2~4주마다 보고 실행 — README·보고서 말미에 안내.

## 6. 텔레메트리 (개발자 수신)

- **기본값 켜짐.** 근거: 대상 사용자가 개발자의 강의 수강 교사로 한정되며 사전 구두 안내가 이뤄짐. 단 ① README에 전송 항목 전문·끄는 방법 명시, ② 끄기는 환경변수 1개로 즉시 가능.
- **세탁(익명화) 필수:** 전송 전 클로드가 이름·경로·이메일·파일 내용 등 식별 정보를 제거하고 일반화 요약만 남긴다. 전송 항목: 분류, 일반화된 교훈 요약, 처방 종류, 플러그인 버전, 언어. 원문 불포함.
- **통로:** Google Apps Script 수신 주소 → 개발자의 구글 시트에 1행씩 적재. 서버 비용 0.
- **알려진 위험(감수):** 수신 주소가 공개 코드에 포함되어 스팸 데이터 가능 → 초기엔 시트에서 수동 필터, 사용자 증가 시 간단한 검증 추가(v2).

## 7. 배포와 IRIS 적용

**저장소:** 깃허브 공개 저장소 1개(이름 `self-improve`, 공개 직전 이름 충돌 검색 → 겹치면 `claude-self-improve`). MIT 라이선스. README 영어(기본)+한국어. 플러그인 명세(manifest) 포함 → `/plugin`에서 저장소 주소로 설치.

**개발 위치:** `IRIS\R07-개발자(Developer)\D06-오픈소스(Open Source)\P01-자기개선(Self-Improve) 〖Plugin〗` (git 저장소 = 이 폴더). 루트 CLAUDE.md 닫힌 목록에 `〖Plugin〗` 태그 추가 완료.

**공개 순서 (개밥먹기 우선):**
1. 구현 → 개발자 IRIS에 user 전역 설치, `SELF_IMPROVE_DIR`을 IRIS 중앙 폴더로 지정
2. `_자기개선(Self-Improvement)` 폴더 생성(`records\`·`reports\`·자체 CLAUDE.md), IRIS-구조지도.html 갱신
3. 2~4주 실사용 → 개선점 반영(이 플러그인이 자기 자신의 첫 고객)
4. 깃허브 공개 + 텔레메트리 활성 확인

**v1 범위:** 기록 + 즉시 제안 + 보고 + 텔레메트리. **v2 후보(README에 목록만):** 칭찬(성공 패턴) 기록, 텔레메트리 대시보드, 전송 검증, 훅 재도입 옵션.

## 8. 결정 이력 (사용자 확정 사항)

| 결정 | 선택 |
|---|---|
| 기록 방식 | 하이브리드(자동 감지 + 수동 명령) |
| 세션 끝 훅 점검 | 삭제 — 그때그때 감지로 일원화 |
| 저장 위치 | 설정 가능, IRIS는 루트 중앙 폴더 |

| 배포 형태 | 클로드코드 플러그인(MCP+스킬 묶음) |
| 이름 | self-improve |
| 텔레메트리 | 구글 시트 수집, 기본값 켜짐(수강생 대상 사전 안내), 세탁 필수 |
